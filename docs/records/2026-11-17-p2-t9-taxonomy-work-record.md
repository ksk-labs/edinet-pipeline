# P2-T9 作業記録: タクソノミの取得と年次更新の自動化、取扱い要領の継続確認

作成: 2026-11-17。チケット: Issue #24 (P2-T9)。仕様: Issue #15 §10。
合格条件8 (未知要素の隔離と警報の故障ケース確認) に対応する。

## 実装の範囲

- `pipeline/taxonomy.py` (新規): 取得・辞書構築・差分・未知要素の隔離・
  継続確認を担うモジュール。副コマンドは check (継続確認) / ingest
  (1版の取込) / run (確認→取込の一括) / diff (辞書2ファイルの差分) /
  quarantine (未知要素の抽出)。
- `.github/workflows/taxonomy_check.yml` (新規): 月次確認 (毎月2日) と
  11月の重点確認 (毎週月曜+1日・11日・21日) で run を実行する。
  警報があれば GitHub Issue を起票する (重複起票は抑止)。
- `taxonomy/indicator_elements.txt` (新規): 指標に効く要素の一覧
  (判断事項の判定用)。正本は指標登録簿 (edinet-definitions の
  indicators.yaml version 3) で、本ファイルはその写し。
- `tests/test_taxonomy.py` (新規): 18件。

## 設計の要点

- 取得元は仕様どおり金融庁の一覧ページと配布ポータルの2か所とし、
  一覧ページを版と ZIP の所在の正本、ポータルを最新版の突合に使う。
  ポータルのダウンロードはファイル名 (ALL_<日付>.zip 等) がページに
  埋め込まれる形であり、実ページで抽出できることを確認した。
- 版の同一性は3つの日付を分けて保持する: 版年 (2026年版)、公表日
  (2025-11-11)、タクソノミ日付 (名前空間内の 2025-11-01)。版年は
  一覧ページの表記を優先し、取れない場合は公表日から導く (11月・
  12月公表は翌年版。2023〜2026年版の実績で確認)。
- 要素辞書は ZIP 内のスキーマの要素宣言とラベルリンクベースから
  構築する (arelle には依存しない。lxml のみ)。キーは Silver の
  element 列と同じ 接頭辞:要素名 とし、タクソノミ日付は別フィールド
  に持つため版をまたぐ差分がキーで取れる。廃止要素は deprecated と
  して保持し、ラベルは deprecatedLabel 役割を予備として取り込む。
- 差分は追加・削除・意味変更 (ラベル・型・期間・バランス・抽象・
  廃止)・日付のみの繰り上がりを分けて数え、改名候補 (日英ラベル
  完全一致の削除+追加) と分割候補 (ラベル包含の削除+複数追加) を
  候補として提示する。候補は確定しない。
- 指標に効く要素に触れる差分は judgment_items として警報に上げる。
  意味判断はユーザーの判断事項であり、本モジュールは指標登録簿を
  変更しない (確定までは旧対応で運転を継続するのが仕様)。
- 未知要素の隔離: Silver の要素名のうち、接頭辞が辞書にある標準
  要素で辞書に無いものを未知とする。提出者拡張の要素 (接頭辞が
  辞書に無い) は P2-T10 の範囲として対象外にした。
- arelle の追随確認: 有効一覧 (edinet-taxonomies.xml) に版の最新
  日付が含まれることを必須とし、同梱される旧日付の未収載は
  uncovered_legacy として情報に留める (理由は下記「実地確認」)。
- 取扱い要領の継続確認: JPX の証券コード協議会「関係資料等」
  ページから codestock_<日付>.pdf を動的に発見し、ページと PDF の
  ハッシュを状態と比較する。状態は v2 データセットの
  taxonomy/state.json に置く (codelist と同じ流儀)。
- 保存先は v2 データセットの taxonomy/ 配下 (版ごとの不変保存+
  目録+原形 ZIP のアーカイブ)。codelist の流儀に揃えた。

### must-fix

  これにより、確認のみ (mode=check) の実行で検出が消費されず、

  へ記録するようにした。あわせてポータルのハッシュを state にも
  保存するようにした (従来は結果にだけ残っていた)。

  - 未決事項: indicator_elements.txt の機械生成または登録簿との

  - 開始点 (発動条件): 指標登録簿 (ksk-labs/edinet-definitions の

    登録簿の版を taxonomy の月次確認で突合する工程の追加も同じ
    未決に含める。発動までは、登録簿の変更と同じ変更で本ファイル
    を更新する手作業の運用 (ファイル冒頭に明記) を継続する。
- S5 (年次ワークフローで隔離が走らない): 配線はせず、到達点の

  未知要素の隔離と警報を故障ケースで確認できることであり、単体
  テストと実辞書での作為的故障ケースで既に満たされている。
  一方 --silver-elements の配線には日次 Silver の要素一覧の供給
  経路が必要だが、その接続点は S2-T5 側で未確定であり (本記録の
  未決点にも既記)、存在しない入力を前提にした配線はワークフロー
  を壊すか形だけのものになる。したがって本修正では、
  pipeline/taxonomy.py 冒頭の説明を「年次更新は完全自動 (隔離を
  含む)」から、隔離は Silver 要素一覧が渡された場合に行い年次
  ワークフローでは未実施である旨の文面に訂正した。接続自体は
  S2-T5 の接続点の確定を開始点とする未決として残る。
- S6 (警報 Issue のタイトル単位の重複抑止): 対応した。
  taxonomy_check.yml の警報起票は、同タイトルの open な Issue が
  ある場合は新規起票を止めるのではなく、その Issue へ新しい
  警報をコメントとして追記するようにした。
- S7 (意味変更項目への substitutionGroup の追加): 対応した。
  意味変更の判定項目に substitution_group と element_id を追加
  した。namespace はタクソノミ日付を含むため、項目に入れると
  日付のみの繰り上がり (date_only) と分離できなくなるので
  対象外とした (判定項目の定義箇所に理由を注記した)。
- S8 (不変保存の競合判定が meta ハッシュのみ): 対応した。競合の
  判定に保存済みの要素辞書自体のハッシュ (meta の sha256_elements
  と実物の照合) を加えた。meta が無く elements だけが別内容で
  先行保存された部分状態は競合として扱い、meta だけを新内容で
  書かない。あわせて quarantine.jsonl の保存に「リモートにあれば
  送らない」ガードを付けた。

### MF-1 (parse_list_page が実ページから版を抽出できない)

- 原因: 実ページの一覧は版ごとの日付別詳細ページ
  (/search/<公表日YYYYMMDD>.html) へのリンクであり、ZIP へのリンクは
  詳細ページ側にある。一覧ページ自体には 1c_Taxonomy.zip が含まれない
  (2026-11-19 に実ページを取得して確認: 一覧 37,163 バイト、詳細ページ
  20251111 には /search/20251111/1c_Taxonomy.zip のリンクが実在)。
  一方 parse_list_page は一覧ページから ZIP リンクを直接探していた。
  テストのフィクスチャが「一覧ページに ZIP への直接リンクがある」構造
  だったため、テストでは検出できなかった。
- 修正: parse_list_page は詳細ページへのリンク (版年表記・公表日・
  詳細ページ URL) の抽出に変え、新設の parse_detail_page (詳細ページ
  から ZIP URL を抽出) と fetch_editions (詳細ページを辿って ZIP URL
  を解決する) を追加した。run_check は fetch_editions を使う。
  最新の版が解決できない場合は TaxonomyError とし、古い版は詳細
  ページに ZIP リンクが無いもの (初期の版は配布形式が違う。実測では
  2009年版の詳細ページに 1c_Taxonomy.zip が無い) や取得に失敗した
  ものを結果から除く。
- 実ページでの確認: 修正後の fetch_editions で実の一覧ページから
  10版 (2026年版〜2018年版) の ZIP URL が解決できた。最新は
  2026年版・公表日 2025-11-11・/search/20251111/1c_Taxonomy.zip で、
  レビュー役の実測と一致する。
- テスト: フィクスチャを実ページの構造 (詳細ページへのリンク形式)
  に差し替え、回帰テストを追加した (詳細ページの解析、一覧→詳細→
  ZIP の解決、最新の版が解決できない場合の失敗、古い版の除外)。
  tests/test_taxonomy.py は 31件から35件になった。修正前コードに
  新しいテストを当てると 9件が失敗し、旧 parse_list_page は実構造の
  フィクスチャから版を 0件しか返さないことを確認した (欠陥の再現)。
  固定版依存の venv で全テスト 139件全件の合格を確認した。
