# P2-T9 作業記録: タクソノミの取得と年次更新の自動化、取扱い要領の継続確認

作成: 2026-11-17。チケット: Issue #24 (P2-T9)。仕様: Issue #15 §10。
合格条件8 (未知要素の隔離と警報の故障ケース確認) に対応する。

## 実装の範囲

- `pipeline/taxonomy.py` (新規): 取得・辞書構築・差分・未知要素の隔離・
  継続確認を担うモジュール。副コマンドは check (継続確認) / ingest
  (1版の取込) / run (確認→取込の一括) / diff (辞書2ファイルの差分) /
  quarantine (未知要素の抽出)。
- `.github/workflows/taxonomy_check.yml` (新規): 月次確認 (毎月2日) と
  11月の重点確認 (毎週月曜+1日・11日・21日) で run を実行する。
  警報があれば GitHub Issue を起票する (重複起票は抑止)。
- `taxonomy/indicator_elements.txt` (新規): 指標に効く要素の一覧
  (判断事項の判定用)。正本は指標登録簿 (edinet-definitions の
  indicators.yaml version 3) で、本ファイルはその写し。
- `tests/test_taxonomy.py` (新規): 18件。

## 設計の要点

- 取得元は仕様どおり金融庁の一覧ページと配布ポータルの2か所とし、
  一覧ページを版と ZIP の所在の正本、ポータルを最新版の突合に使う。
  ポータルのダウンロードはファイル名 (ALL_<日付>.zip 等) がページに
  埋め込まれる形であり、実ページで抽出できることを確認した。
- 版の同一性は3つの日付を分けて保持する: 版年 (2026年版)、公表日
  (2025-11-11)、タクソノミ日付 (名前空間内の 2025-11-01)。版年は
  一覧ページの表記を優先し、取れない場合は公表日から導く (11月・
  12月公表は翌年版。2023〜2026年版の実績で確認)。
- 要素辞書は ZIP 内のスキーマの要素宣言とラベルリンクベースから
  構築する (arelle には依存しない。lxml のみ)。キーは Silver の
  element 列と同じ 接頭辞:要素名 とし、タクソノミ日付は別フィールド
  に持つため版をまたぐ差分がキーで取れる。廃止要素は deprecated と
  して保持し、ラベルは deprecatedLabel 役割を予備として取り込む。
- 差分は追加・削除・意味変更 (ラベル・型・期間・バランス・抽象・
  廃止)・日付のみの繰り上がりを分けて数え、改名候補 (日英ラベル
  完全一致の削除+追加) と分割候補 (ラベル包含の削除+複数追加) を
  候補として提示する。候補は確定しない。
- 指標に効く要素に触れる差分は judgment_items として警報に上げる。
  意味判断はユーザーの判断事項であり、本モジュールは指標登録簿を
  変更しない (確定までは旧対応で運転を継続するのが仕様)。
- 未知要素の隔離: Silver の要素名のうち、接頭辞が辞書にある標準
  要素で辞書に無いものを未知とする。提出者拡張の要素 (接頭辞が
  辞書に無い) は P2-T10 の範囲として対象外にした。
- arelle の追随確認: 有効一覧 (edinet-taxonomies.xml) に版の最新
  日付が含まれることを必須とし、同梱される旧日付の未収載は
  uncovered_legacy として情報に留める (理由は下記「実地確認」)。
- 取扱い要領の継続確認: JPX の証券コード協議会「関係資料等」
  ページから codestock_<日付>.pdf を動的に発見し、ページと PDF の
  ハッシュを状態と比較する。状態は v2 データセットの
  taxonomy/state.json に置く (codelist と同じ流儀)。
- 保存先は v2 データセットの taxonomy/ 配下 (版ごとの不変保存+
  目録+原形 ZIP のアーカイブ)。codelist の流儀に揃えた。

## 実地確認 (2026-11-17、現在のタクソノミでの実測)

取得元から実際に取得して確認した。版年の対応は次のとおり:
2025年版 = 公表 2024-11-12、タクソノミ日付 2024-11-01。
2026年版 = 公表 2025-11-11、タクソノミ日付 2025-11-01 (最新版)。

- ZIP の取得 (金融庁の一覧ページ配下の実 URL から):
  - 2025年版: 5,896,857 バイト、SHA-256 70abacba…ae90
  - 2026年版: 5,933,638 バイト、SHA-256 8d57f848…de2
- 要素辞書の構築:
  - 2025年版: 要素 11,066 件 (現行 9,723 件・廃止 1,343 件)、
    日本語・英語ラベル各 11,064 件
  - 2026年版: 要素 11,129 件 (現行 9,699 件・廃止 1,430 件)、
    日本語・英語ラベル各 11,127 件。現行要素でラベルが無いのは iod と
    jppfs_pe の構造要素2件のみ (配布物側の実態であり抽出の欠落では
    ないことを、ラベルファイルに当該要素が存在しないことで確認)。
- 実差分 (2025年版→2026年版): 追加 63、削除 0、意味変更 113
  (内訳: jptoo-ton 54、jptoi 20、jplvh 17、jppfs 10、jptoo-pst 7、
  jpcrp 4、jpigp 1。内容はラベルの条文番号の追随や表記の統一、
  廃止への移行が中心)、日付のみの繰り上がり 10,623、改名候補 0、
  分割候補 0。指標に効く要素 (12件) への差分は 0 件であり、
  judgment_items は空だった。
- 未知要素 (合格条件8の故障ケース確認): 試作 Silver 標本
  (silver_sample.parquet、相異なる要素 1,491 件) を実辞書と照合し、
  2026年版辞書では未知 0 件、2025年版辞書では 2 件 (2026年版で
  追加された要素) を検出した。作為的な未知要素
  (jppfs_cor:DefinitelyNotARealElement999) を混ぜた故障ケースでは
  その1件だけが隔離され、提出者拡張の要素は対象外になった。
  CLI の quarantine は未知ありで終了コード 1 を返す。
- arelle の追随確認: 上流 (Arelle/Arelle master) の有効一覧は、
  ローカル導入済み arelle 2.47.5 の同梱ファイルとバイト一致
  (SHA-256 cf204dd2…cb12)。収載日付は 2013-08-31、2024-11-01、
  2025-11-01 で、2026年版の最新日付 2025-11-01 を含む (追随済み)。
  一方、2026年版に同梱される 2021-11-01 (jpcrp-sbr / jpctl) は
  一覧に無い。これを必須にすると常時警報になるため、必須対象を
  版の最新日付に限る設計にした (2026-11-17 の検証実測でも、有効
  一覧は主要体系のみを収載する形だった)。
- 配布ポータル: 実ページ (309,609 バイト) から配布ファイル 136 件を
  抽出し、最新 ALL は 2025-11-01 で一覧ページの最新版と一致した。
- 取扱い要領: 関係資料ページ (SHA-256 9ff7a5f3…0edb) から
  codestock_20250701.pdf を発見し、PDF (119,534 バイト、
  SHA-256 676b7817…af0f7) のタイトルが「株式及び公社債銘柄コードの
  設定、変更及び削除に関する取扱い要領」であり、最終改定が
  2025年7月であることを本文で確認した。
- テスト: tests/test_taxonomy.py の 18 件が合格。全テストでは
  既存の test_parse.py の1件が変更前から失敗する (本変更とは無関係。
  ローカル環境の pyarrow/numpy の組合せに起因する疑い。CI は
  requirements.txt の固定版で実行される)。

## 判断事項として残した差分の扱い

- 今回の実差分 (2025→2026) では指標に効く要素への差分は無かった。
- 将来の年次更新で judgment_items が出た場合は、警報 (実行サマリと
  GitHub Issue) として上がり、意味判断と指標登録簿の更新は
  ユーザーの判断を経てから行う。自動では対応を変更しない。
