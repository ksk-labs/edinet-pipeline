## 残りの月の進め方 (67か月: 2016-04〜2021-10)

1. 月ごとに backfill.yml を workflow_dispatch で順次投入する
   (inputs.months に1か月だけを指定する。並行 dispatch はしない)。
   年単位でカンマ区切りの一括指定も第1期で実績があるが、失敗時の
   切り分けと再開の粒度を優先し、原則は月単独とする。進捗が安定した
   塊では複数月の一括指定も可 (その場合も投入は1回ずつ順に行う)。
2. 各月の完了ごとに、v2 の silver/month=YYYY-MM/ に3点
   (ledger.jsonl・run_summary.json・silver.parquet) が揃うことを
   確認する。揃わない月・失敗した run は、その月だけを再 dispatch
   する (目録の自己回復で未完分だけが処理される。再実行は冪等)。
3. 照合は月ごと、または数か月まとめて、reconcile_backfill.py を
   --since 2016-03-01 --until <対象末日> で実行し、未説明の差分が
   ゼロであることを確認する。2017-06 を含む範囲では、説明済みの
   zip 無し 1件 (S100AFCF) が no_zip_path に現れるのが正常。
4. 全68か月が揃ったら、第2期の全範囲 (2016-03-01〜2021-10-31) で
   全数照合を行い、母数 108,110 = ok 108,109 + 説明済み 1、
   failed 残り 0、行数一致をもって Issue #13 の受け入れ条件とする。
   あわせて第1期と合わせた全期間の照合 (413,772件) も確認する。
5. 月あたりの所要時間の目安: 2016-03 (414件) で約2分。
   件数の多い月 (例: 2021-06 の 7,807件) は第1期の実績から
   数十分〜数時間を見込む。Actions の timeout は350分で、
   大きな月が途中で止まっても再 dispatch で続きから進む。
