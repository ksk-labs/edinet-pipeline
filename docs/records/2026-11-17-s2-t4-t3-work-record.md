## 変更内容

- `pipeline/ledger.py` (新規): 追記型 JSONL 目録の共通土台 `JsonlLedger`
  を切り出した。読み込み (壊れた行の無視と corrupt_lines の数え上げ)、
  追記 (flush + fsync 後に最新行と試行回数を更新)、キー関数による
  一般化を1か所に集約した。試行回数 (attempts) の数え上げは、統合前の
  batch.Ledger の振る舞いを土台へ引き上げた (キーが取れない行は数えない)。
- `pipeline/batch.py`: `Ledger` を `JsonlLedger` の特殊形にした
  (キーは doc_id)。固有の意味は `is_done` (最新行が ok で、入力 zip の
  ハッシュが一致し、出力シャードが実在する場合だけ処理済み) のみ。
- `pipeline/discovery.py`: ローカルの `JsonlLedger` 定義を削除し、
  土台を import する形にした (名前は従来どおり discovery からも参照できる)。
- `verification/reconcile_backfill.py`: 対象期間の終了日 `--until` を
  追加した (省略時は従来どおり上限なし)。第2期 (2021-10 以前) の照合に使う。
- `tests/test_ledger.py` (新規): 統合の回帰テスト7件。土台の追記・再読込・
  壊れた行・キーなし行、batch.Ledger の attempts と is_done、同一ファイルを
  両方のビューで読んだときの一致、run_batch + combine の合成回帰。

## 回帰確認 (実測)

- テスト一式: 統合前 (main) 61件すべて合格 → 統合後 68件すべて合格
  (新規7件を含む)。
- 第1期の全数照合を再実行し、結果が従来と一致することを確認した:
  照合スクリプト exit=0、母数 305,662 = 変換 ok 305,412 + 説明済み
  zip 無し 250、failed 残り 0、欠落0・余分0・行数不一致0、
  行数合計 50,560,027行 (目録と結合 parquet で一致)。
  第1期の成果物 (v2 の silver/month=2021-11〜2026-11) は壊れていない。
- 振る舞いの差分として意図した変更は1点だけ: batch.Ledger.append は
  doc_id を持たない行で例外にならず、状態に数えないようになった
  (呼び出し側は全て doc_id つきで渡すため、実運用の振る舞いは変わらない)。
