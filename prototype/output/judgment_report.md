## 本実装への申し送り（open_caveats）

(a) **convert.py の nil 判定の名前空間の取り違え**（分類表示のみ）: convert.py は nil 属性を XBRL インスタンスの名前空間で探していたが、実際の属性は XMLSchema-instance 名前空間の xsi:nil である。そのため nil 判定が一度も働かず、nil 事実 2,710件が「unparseable（数値として読めなかった）」に、unitRef の無い nil 310件が non_numeric に分類されていた（T4 で特定）。Silver の数値そのものに影響はない。本実装では xsi:nil で判定し、nil を独立した分類として数えること。

(b) **Inline XBRL 抽出の寄与が標本では0件**: convert.py の Inline XBRL 抽出は、HTML パーサがタグ名を小文字化するため nonFraction に一致せず、抽出件数そのものが0件だった（T4 で特定）。Silver の事実はすべて .xbrl インスタンス由来であり、ixbrl のみに存在する事実（米国基準の連結本表など）に届いていない（T5 の申し送り）。本実装では変換の抽出範囲の見直しが要る。

(c) **Silver に次元（連結/単体）情報が無い**: Silver の dimension 列は全行空だった（検証役の実測でも非空は 0／22,194行）。連結/単体・セグメントの区別は原文 context の次元にあるが、Silver に落ちていない。Gold では格納順（原文の記載順）で判別したが、本実装では Silver に次元を持たせること（T5 の申し送り）。

補助の観察: 提出者拡張要素の要素名は、名前空間の末尾セグメントに提出日を含むため、同一要素でも書類ごとに文字列が変わる（合格条件3の根拠を参照）。本実装で要素の同一性を判定する際は、拡張要素の正規化が必要である。
